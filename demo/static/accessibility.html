Accessibility

Ways to explore the research, and known gaps.

01Our approach

The showcase is designed to make its main explanation and results available in text as well as visually. Speech is optional; the English prediction and dataset reference remain visible. This page describes current features and limitations, rather than claiming formal accessibility certification.

02Navigation and playback

  • A skip link takes keyboard users to the main content. Links and controls have visible focus indicators.
  • Use Tab to reach the pipeline stages. Arrow keys switch stages; Home and End jump to the first and last stage.
  • The timeline and feature controls can be operated with the keyboard. Playback starts only when requested, and the walkthrough can be explored one stage at a time.
  • The walkthrough respects the device’s reduced-motion preference by using manual stage progression instead of an automatic tour.
  • Speech needs a separate action and an available local English voice. It can be stopped independently of the walkthrough.

03Text alternatives

The Research Notes explain the pipeline, evaluation and limitations without requiring the animation. The comparison table provides exact values alongside the chart. Feature controls expose the selected frame, channel and coordinate values as text.

Recorded clips are silent. Where available, their English reference translations and model predictions appear at the English stage. The reference is a translation from the dataset, not a full description of every visible movement.

04Known limitations

The detailed pose, feature and attention visualisations use canvas. Their labels and numeric readouts do not yet provide a complete nonvisual equivalent of every visual relationship. Each signing clip also lacks a full descriptive transcript of its visual content.

Assistive-technology behaviour varies by browser. The project has not completed an independent accessibility audit or comprehensive testing with Deaf signers and assistive-technology users. Model translation errors remain a separate limitation from interface accessibility.

05Report a barrier

Email @example.org with the page, the task you were trying to complete and the barrier you encountered. If useful, include your browser and assistive technology. You do not need to send a camera recording or disclose a disability.

You can also request an alternative explanation of research content. We will discuss a format that is practical for you.
